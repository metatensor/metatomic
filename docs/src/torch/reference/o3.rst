O(3) symmetries
===============

The :py:mod:`metatomic.torch.o3` module provides tools to deal with `O(3)`
symmetries. First it offers functions to rotate and invert
:py:class:`~metatomic.torch.System` and :py:class:`~metatensor.torch.TensorMap`
objects, for example to generate randomly rotated copies of a structure for data
augmentation. Second, it offers tools to convert
:py:class:`~metatensor.torch.TensorMap` between Cartesian and spherical forms.

.. _o3-conventions:

Conventions for O(3) representations
------------------------------------

To transform a :py:class:`~metatensor.torch.TensorMap` (or a
:py:class:`~metatensor.torch.TensorBlock`), the
:py:func:`O3Transformations.transform_tensormap` (resp.
:py:func:`O3Transformations.transform_block`) need to know, for each component
axis, whether it carries a Cartesian or a spherical tensor. This is inferred
from the axis name: axis, whether it carries a Cartesian or a spherical tensor.
This is inferred from the axis name:

- Cartesian axes are named ``xyz``, or ``xyz_1``, ``xyz_2``, ... for blocks with
  several Cartesian axes (e.g. rank-2 Cartesian tensors). These are rotated
  directly with the (3, 3) transformation matrix :math:`R` passed to
  :py:class:`O3Transformations`, following the usual column-vector convention
  :math:`v' = R v` (equivalently, since values are stored as rows,
  ``values_transformed = values @ R.T``).
- Spherical axes are named ``o3_mu``, or ``o3_mu_1``, ``o3_mu_2``, ... They are
  rotated with the real Wigner-D matrix for the angular momentum ``o3_lambda``
  (respectively ``o3_lambda_1``, ``o3_lambda_2``, ...) found in the block's key.
  Real, rather than complex, spherical harmonics are used throughout, matching
  the convention used elsewhere in metatomic and metatensor for spherical
  targets.

Wigner-D matrices
^^^^^^^^^^^^^^^^^

Complex Wigner-D matrices are computed by the `wigners <https://github.com/luthaf/wigners>`_
package, using the convention

.. math::

    D^{\ell}_{m',m}(\alpha, \beta, \gamma) = \langle \ell, m' |
        e^{-i J_z \alpha} e^{-i J_y \beta} e^{-i J_z \gamma} | \ell, m \rangle,

with ZYZ Euler angles :math:`(\alpha, \beta, \gamma)` extracted from the proper
part of :math:`R`, i.e. from :math:`R` itself when :math:`\det R = 1`, or from
:math:`-R` when :math:`\det R = -1`, such that this proper part equals
:math:`R_z(\alpha) R_y(\beta) R_z(\gamma)`.

These are then converted to real Wigner-D matrices through the unitary
change of basis :math:`T` mapping complex spherical harmonics
:math:`Y_{\ell}^{m}` to real ones:

.. math::

    Y_{\ell, m}^{\text{real}} = \begin{cases}
        \dfrac{1}{\sqrt{2}} \left( Y_{\ell}^{-m} + (-1)^m Y_{\ell}^{m} \right)
            & m > 0 \\[6pt]
        Y_{\ell}^{0} & m = 0 \\[6pt]
        \dfrac{i}{\sqrt{2}} \left( Y_{\ell}^{m} - (-1)^m Y_{\ell}^{-m} \right)
            & m < 0
    \end{cases}

so that the real Wigner-D matrix is :math:`D^{\ell}_{\text{real}} = T^{*}
D^{\ell} T^{T}`. Spherical components follow the same column-vector convention
as Cartesian ones, :math:`f' = D^{\ell}_{\text{real}} f` (equivalently, since
values are stored as rows, ``values_transformed = values @ D.T``).

For an improper rotation (a rotation composed with an inversion), Cartesian axes
are flipped as part of the transformation matrix itself, while spherical axes
pick up an extra parity factor :math:`(-1)^{\ell} \sigma`, where :math:`\ell` is
``o3_lambda`` and :math:`\sigma` is the block's ``o3_sigma`` (its behavior under
inversion, +1 or -1), also read from the key.

A :py:class:`~metatensor.torch.TensorBlock` in general contains values
associated with several systems. This information is contained in the
``"system"`` samples dimension; each row is rotated with the transformation of
the system it belongs to. Gradient blocks are routed the same way, via their
parent block's ``"system"`` column. When only one system is being transformed,
the ``"system"`` column is optional and, if present, is ignored: every row is
rotated with the (single) given transformation.

Cartesian and spherical tensors
-------------------------------

:py:func:`~metatomic.torch.o3.cartesian_to_spherical` converts a Cartesian
tensor of arbitrary rank, stored on a product basis with one ``xyz_1``,
``xyz_2``, ... component axis per Cartesian index, into a set of blocks on a
basis of real spherical harmonics (with a single ``o3_mu`` component axis, and
``o3_lambda`` / ``o3_sigma`` keys). This is done by coupling the Cartesian
components two by two with Clebsch-Gordan coefficients, starting from the last
ones. For tensors of rank 3 and above, there are multiple ways to get the same
``o3_lambda``, and the coupling history is stored in additional ``l_{i}`` and
``k_{i}`` keys. :py:func:`~metatomic.torch.o3.spherical_to_cartesian` performs
the inverse transformation. These functions can be used from TorchScript, in
which case the Clebsch-Gordan coefficients have to be computed in advance with
:py:func:`~metatomic.torch.o3.calculate_cg_coefficients`.

Coupled and uncoupled spherical tensors
---------------------------------------

A block with several spherical component axes ``o3_mu_1``, ``o3_mu_2``, ...
(with the corresponding ``o3_lambda_1`` / ``o3_sigma_1``, ``o3_lambda_2`` /
``o3_sigma_2``, ... keys) transforms like a product of spherical harmonics. This
is the uncoupled form, used for example for the blocks of a Hamiltonian
expressed on a basis of atomic orbitals.
:py:func:`~metatomic.torch.o3.uncoupled_to_coupled` uses Clebsch-Gordan
coefficients to transform such a tensor into the coupled form, where each block
has a single ``o3_mu`` component axis and transforms like a single spherical
harmonic, with degree and parity given by the ``o3_lambda`` and ``o3_sigma``
keys. The degrees and parities of the uncoupled components are kept in the
``l_1`` / ``s_1``, ``l_2`` / ``s_2``, ... keys of the coupled tensor, and
:py:func:`~metatomic.torch.o3.coupled_to_uncoupled` uses them to perform the
inverse transformation. As for the conversion between Cartesian and spherical
tensors, the Clebsch-Gordan coefficients have to be computed in advance with
:py:func:`~metatomic.torch.o3.calculate_cg_coefficients` to use these functions
from TorchScript.
